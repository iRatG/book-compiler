## О чем эта книга

Практическое руководство о том, как писать код, который остается понятным, простым в модификации и устойчивым к изменениям. Основано на идее, что человеческий мозг имеет когнитивные пределы - хороший код должен умещаться в голове разработчика.

Книга охватывает эвристики (практические правила) для:
- Управления сложностью на уровне функций, модулей и архитектуры
- Тестирования кода (TDD, outside-in approach)
- Проектирования API
- Работы в команде
- Обслуживания и расширения существующего кода

- Программирование - это искусство или наука?
- Почему программировать сложнее, чем кажется?
- Как управлять сложностью?
- Как правильно тестировать?

### 3. **02_ideas.md** - Ключевые идеи и принципы
12 основных принципов:
1. Эвристики важнее правил
2. Код читается больше, чем пишется
3. Когнитивная нагрузка - главный враг
4. Инкапсуляция - защита инвариантов
5. Декомпозиция - управление сложностью
6. Вертикальный срез - лучший способ начать
7. Outside-in тестирование
8. API дизайн как дизайн вызывающего кода
9. Чек-листы спасают жизни
10. Коллективное владение кодом
11. Паттерны для расширения легаси-кода
12. Рабочий процесс - часть архитектуры

### 4. **03_reasoning.md** - Аргументы и доказательства
10 детальных аргументов с примерами и научным обоснованием:
- Экспоненциальный рост затрат при усложнении кода
- Код, умещающийся в голове, как профилактика ошибок
- Почему чек-листы работают
- Инкапсуляция как контракт
- Вертикальный срез для ранного выявления ошибок дизайна
- И другие...

### 5. **04_consequences.md** - Практические применения

- Метрики размера функций (80x24, цикломатическая сложность)
- Инкапсуляция и защита инвариантов

- Strangler Pattern для улучшения легаси-кода
- Feature Flags для безопасного развертывания
- Организация код-ревью как обучение
- Тайм-боксинг для сохранения фокуса
- И другие...

## Как использовать этот анализ

1. **Для быстрого ознакомления**: прочитайте 00_purpose.md и 01_questions.md (10-15 минут)

2. **Для глубокого понимания**: прочитайте все 5 файлов в порядке (1-2 часа)

3. **Для практического применения**: начните с 04_consequences.md и внедрите по одной рекомендации в неделю

4. **Для кросс-ссылок**: используйте теги для поиска пересечений с другими книгами в коллекции

5. **Для обсуждения в команде**: используйте вопросы из 01_questions.md как начало обсуждения
