# Чистый код: Слой РАССУЖДЕНИЕ

---

## Arg-001: Плохой код замедляет разработку экспоненциально

Мартин показывает историю компании, которая:
- Месяц 1: двигается быстро
- Месяц 3: скорость падает в 2 раза (технический долг)
- Месяц 12: скорость упала в 10 раз (болото кода)
- Месяц 18: новая фича стоит в 100 раз дороже

Вывод: написать код правильно сначала дешевле, чем переписывать.

---

## Arg-002: Читаемость кода важнее производительности для 99% кода

Пример:
- Оптимизация производительности может ускорить код на 10%
- Но если код нечитаем, поддержка занимает в 10 раз больше времени

Поэтому: читаемость первична.

---

## Arg-003: Единственный способ идти быстро - писать чистый код

Противоречие: кажется, что спешка требует грязного кода. На самом деле:
- Чистый код пишется быстрее (нет переделок)
- Грязный код замедляет (потом переделываем)

Реальное время: чистый код медленнее сначала, но быстрее потом.

## Ev-001: Пример плохого кода (Глава 2)

```java
// Плохо
public List<int[]> getThem() {
  List<int[]> list1 = new ArrayList<int[]>();
  for (int[] x : theList)
    if (x[0] == 4)
      list1.add(x);
  return list1;
}

// Хорошо
public List<Cell> getFlaggedCells() {
  List<Cell> flaggedCells = new ArrayList<Cell>();
  for (Cell cell : gameBoard)
    if (cell.isFlagged())
      flaggedCells.add(cell);
  return flaggedCells;
}
```

Второй вариант: сразу понимаешь, что делает функция.

## Ev-002: Пример функции нарушает принципы (Глава 3)

```java
// Плохо - функция делает много
public Boolean save(User user) {
  validateUser(user);      // валидирует
  encryptPassword(user);   // трансформирует
  database.save(user);     // сохраняет
  sendEmail(user);         // отправляет письмо
  return true;             // возвращает результат
}

// Хорошо - одна ответственность
public void save(User user) {
  validateUser(user);
  User encryptedUser = encryptPassword(user);
  database.save(encryptedUser);
}
// Email отправляется отдельно (event listener или другой сервис)
```
