# The Software Architect Elevator — Agent Rules

## WHEN TO USE THESE PRINCIPLES
- Organizational and architectural decisions
- Leadership and change management
- Technology strategy discussions
- Decision documentation (ADRs)

## HOW TO APPLY

### Rule 1: Ride the Elevator
Up (boardroom: strategy, budget) ↔ Down (engine room: code, constraints)
Do this consistently to build credibility

### Rule 2: Decision Framework
1. Identify reversible vs. irreversible
2. For irreversible: Use structured decision-making
3. For reversible: Decide quickly; change later
4. Document decision + reasoning (ADR)

### Rule 3: Optionality Preservation
Minimize irreversible decisions
Use generic abstractions where possible
Defer decisions until more is known

### Rule 4: Automation Strategy
Identify high-risk manual processes
Automate by: impact × frequency

### Rule 5: Culture Assessment
Identify limiting beliefs
Plan shifts through evidence + incentives

### Rule 6: Influence Building
Engage in code reviews
Help debug critical issues
Deliver on promises
Don't blame people; change systems

### Rule 7: Communication Strategy
Tell stories, not mandates
Show concrete examples
Demonstrate value through data

---

## WHEN UNCERTAIN

**Q: Should architects code?**
A: YES. Engagement in engine room essential for credibility

**Q: How do I influence without authority?**
A: Build credibility through consistent delivery; earn trust

**Q: Should we automate this process?**
A: If high-impact and high-frequency: YES

---

## COMMON MISTAKES

❌ Stay in boardroom only (disconnect from reality)
✅ Ride both directions consistently

❌ Mandate architectural decisions
✅ Influence through stories and evidence

❌ Tolerate manual high-risk processes
✅ Automate everything possible
