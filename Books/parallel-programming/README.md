## Центральная Идея

**Параллельное программирование не о потоках — это о координации.**

Существует не один "правильный" способ писать параллельный код. Вместо этого:
- **Shared Memory (Locks):** Подходит для низкой латентности и локальной координации
- **Message Passing (Actors):** Лучше для слабой связанности и распределённых систем
- **Lock-Free (Atomics):** Для экстремальной производительности и высокой конкуренции
- **Immutability:** Для безопасности и простоты мышления

**Мастерство приходит от понимания компромиссов.**

## Ключевые Темы

### Фундаментальные Концепции
- **Concurrency vs. Parallelism:** Одновременность (кажущаяся) vs. Параллелизм (реальная)
- **Thread Safety:** Безопасность потоков через взаимное исключение + видимость памяти
- **Memory Visibility:** Гарантии видимости изменений между потоками
- **Happens-Before Relations:** Порядок операций и барьеры памяти

### Механизмы Синхронизации
- **Locks/Monitors:** Мьютекс, семафоры, мониторы
- **Atomic Operations:** Атомарные операции и CAS (Compare-And-Swap)
- **Lock-Free:** Алгоритмы без блокировок
- **Message Passing:** Асинхронная коммуникация

### Паттерны Параллелизма
- **Fork-Join:** Разделяй-и-властвуй параллелизм
- **Map-Reduce:** Распределённая обработка
- **Pipeline:** Конвейерная архитектура
- **Actor Model:** Изолированные агенты с сообщениями
- **Producer-Consumer:** Асинхронная очередь

### Масштабирование
- **Amdahl's Law:** Закон ограничения параллелизма
- **False Sharing:** Конфликт кэш-линий между потоками
- **Contention:** Конкуренция за общие ресурсы
- **CAP Theorem:** Компромисс в распределённых системах

## Ключевые Выводы

### Что нужно знать в первую очередь
1. **Параллелизм сложен:** Thread-safety — это не только мьютексы
2. **Выберите модель:** Shared memory, actors, lock-free, immutable
3. **Компромиссы везде:** Нет универсального решения
4. **Тестирование недостаточно:** Нужна формальная дисциплина

### Антипаттерны (избегайте)
- ❌ "Просто добавь lock" (может привести к deadlock)
- ❌ Смешивание моделей без понимания (race conditions)
- ❌ Оптимизация без профилирования (false sharing)
- ❌ Релиф на тестировании (Heisenbug)

### Лучшие практики
- ✅ Выбирайте модель в зависимости от домена
- ✅ Документируйте гарантии thread-safety
- ✅ Профилируйте под реальной нагрузкой
- ✅ Используйте инструменты верификации
