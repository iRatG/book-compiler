**Версия:** 1.0 (вручную, будет автоматизировано завтра)

**Язык:** Русский

---

## Что это?

Это центральный узел **знаниевой сети**, которая объединяет идеи, принципы и практики из всех разобранных книг через систему **тегов**.

Каждая книга в `Books/` разобрана по 5-слойной методологии:
- `00_purpose.md` — Проблема и цель
- `01_questions.md` — Центральные вопросы
- `02_ideas.md` — Ключевые идеи с тегами (`#тег`)
- `03_reasoning.md` — Аргументы с тегами
- `04_consequences.md` — Практические применения с тегами

Эта библиотека **собирает все теги**, выявляет **пересечения между книгами** и создаёт **единую навигацию** по системе знания.


## Как пользоваться

### Вариант 1: Поиск по тегу
1. Открыть `tags-registry.md`
2. Найти интересующий тег
3. Перейти на страницу в `concepts/`
4. Увидеть все места где этот тег встречается в разных книгах

**Пример:**
```
Ищу #тестирование
→ tags-registry.md показывает: используется в Clean Arch, Pragmatic, Code That Fits
→ Открываю concepts/тестирование.md
→ Вижу где о тестировании говорит каждая книга
→ Кликаю на ссылку → перейду в конкретную книгу/идею
```

### Вариант 2: Исследование книги
1. Выбираю интересующую книгу из `Books/`
2. Читаю `02_ideas.md` (там все теги)
3. Вижу какие другие книги говорят о той же идее
4. Переходу по ссылке в другую книгу через Library

**Пример:**
```
Читаю Clean Architecture → идея "архитектура как дизайн"
→ Вижу #архитектура в теге
→ Клик на #архитектура → concepts/архитектура.md
→ Вижу что о том же говорят Code That Fits, Parallel Programming
→ Сравниваю подходы через разные книги
```

### Вариант 3: Поиск через Obsidian
1. Открыть Books/ как Obsidian vault
2. Использовать встроенный граф знаний
3. Теги и связи визуализируются автоматически
4. Навигация через граф показывает пересечения

## Пересечения между книгами (примеры)

### Clean Architecture ↔ Code That Fits in Your Head
- Оба говорят о `#архитектура` как о **решениях, которые легко менять**
- Оба заботятся о `#стоимость-изменений`
- Оба используют `#модульность` как основу

### Clean Architecture ↔ Pragmatic Programmer
- Оба про `#профессионализм` как отношение
- Оба про `#тестирование` как управление риском
- Оба про борьбу за качество против давления менеджмента

### Pragmatic Programmer ↔ Code That Fits
- Оба про `#автоматизация` как экономию времени
- Оба про `#код-ревью` как минимум качества
- Оба про `#простота` как стратегия

### Ideal Work ↔ Parallel Programming
- **Неожиданное пересечение:** оба про `#этика`
  - Ideal Work: этика в выборе технологий и влиянии на людей
  - Parallel Programming: этика в правильном выборе модели (не усложнять без причины)

## Как обновляется Library/

**Текущий процесс (v1.0, вручную):**
1. Добавляю новую книгу через skill
2. Skill разбирает её по 5 слоям с тегами
3. Я вручную обновляю `tags-registry.md`
4. Я вручную обновляю или создаю файлы в `concepts/`
5. Коммитю вместе с новой книгой

**Будущий процесс (v2.0, автоматизировано):**
1. Добавляю новую книгу через skill
2. Запускаю `./build-library.sh`
3. Скрипт автоматически:
   - Читает все теги из `Books/*/0*.md`
   - Обновляет `tags-registry.md`
   - Создаёт/обновляет `concepts/*.md`
   - Добавляет перекрёстные ссылки
4. Коммитю всё автоматически обновленное
